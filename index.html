Frequently Asked Questions

Everything You Need To Know

Common questions about migrating, deploying, and scaling on Global.

How is Global different from traditional serverless like AWS Lambda?
Traditional serverless platforms package your application in heavyweight container images or virtual machines that take 200ms to 2 seconds to initialize (cold starts). Global uses isolated V8 execution runtimes that launch in less than 1ms directly in 300+ edge data centers nearest to your end users.
Can I connect to my existing PostgreSQL or MySQL database?
Yes! Global supports standard TCP socket connections with connection pooling over edge relays (Hyperdrive), preventing pool exhaustion and maintaining persistent connections from edge isolates back to your primary database with minimal round trips.
How does Anycast DNS and traffic routing work?
Global announces your IP addresses via BGP from all 300+ edge nodes simultaneously. When an end user makes an HTTP request, the internet's routing infrastructure naturally routes their packets to the closest physical data center, shaving tens or hundreds of milliseconds off every request.
Do you support frameworks like Next.js, Remix, Astro, and SvelteKit?
Yes! Our CLI automatically detects your framework build output and transforms dynamic server-rendered routes into edge isolate workers, while automatically optimizing and caching static assets across global CDN caches.
What happens if my traffic spikes by 100x unexpectedly?
Because edge isolates require virtually zero memory overhead to initialize, traffic spikes are naturally absorbed in parallel across hundreds of nodes worldwide without requiring pre-warming or provisioned concurrency.
